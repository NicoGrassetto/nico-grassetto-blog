A lot of experienced developers are wrestling with exactly this. The interesting thing is that GenAI has changed **what feels worth learning**, but it hasn’t removed the need to learn — it has shifted where the leverage is.

A few themes that come up a lot:

### 1. “Knowing how to code” is becoming less rare; knowing *what should be built* matters more

With AI-assisted coding, many people feel the incentive to memorize APIs, syntax, boilerplate, CRUD patterns, etc. has dropped. You can ask an AI to generate a lot of that.

But the value moves upward:

* architecture decisions
* tradeoffs
* debugging weird failures
* understanding constraints
* security
* performance
* data modeling
* knowing when the AI is wrong

A senior developer is often valuable not because they type faster, but because they can look at generated code and say: “This is a bad idea for five reasons.”

### 2. AI can create a false sense of competence

A common concern is that vibe coding lets people get to the “demo stage” without understanding the system.

Security is a perfect example:

* AI can generate an authentication flow
* it can add JWTs
* it can write database queries
* it can configure cloud resources

…but it may not know your actual threat model. It may miss:

* privilege escalation
* insecure defaults
* leaking secrets
* bad authorization logic
* supply-chain issues
* insecure dependencies

So security knowledge becomes **more important**, not less.

### 3. The incentive changes from “learn everything” to “learn the concepts behind the tools”

Before:

> “I need to learn framework X because my job requires it.”

Now:

> “I need to understand the underlying concept so I can judge AI output.”

Examples:

* Learn SQL concepts, not every ORM API.
* Learn networking basics, not every cloud button.
* Learn authentication models, not just copy an OAuth implementation.
* Learn OS/process/memory concepts, not every container command.

The fundamentals become a kind of “AI supervision skill.”

### 4. Some people actually become more motivated

Another viewpoint is that AI removes the boring barrier:

> “I wanted to build this thing but I didn’t want to spend three days fighting a library.”

Now people can explore:

* game development
* embedded
* security labs
* data science
* automation

because the cost of experimenting is lower.

The people who benefit most tend to be curious people who already have a mental model.

### 5. A useful mental shift: learn things that AI cannot reliably judge for you

A rough hierarchy:

**Low ROI to deeply memorize**

* framework syntax
* boilerplate patterns
* exact library calls

**High ROI**

* computer science fundamentals
* security
* distributed systems
* databases
* networking
* software design
* debugging
* domain knowledge
* product thinking

Security especially is a good one because AI increases the amount of code being produced, which increases the amount of code that can be wrong.

### 6. The “new skill” is becoming AI-assisted engineering

A modern developer skill set looks less like:

> “I can write 100 lines of code from scratch.”

and more like:

> “I can take an ambiguous problem, design a solution, guide AI, verify the output, test it, secure it, and maintain it.”

The last parts are where experienced developers still differentiate themselves.

Given that you’re already not new to coding, I’d actually argue your position is one of the better ones: you don’t need to compete with AI at typing code. You can use it as a multiplier while deliberately filling gaps like security, architecture, and systems thinking. Those are exactly the areas where shallow AI-generated solutions tend to break.
